# FAZ 02 pure framing engine

Owned files: `src/modules/framing/geometry.ts`, `engine.ts`, `validation.ts`, `tests/framing-engine.test.ts` and this report. No UI, storage or project changes are included here.

The engine accepts a DrawingDocument, explicit settings and caller supplied identifiers/time. It uses no random values, clock, storage or UI state. Geometry signatures retain exact outer/void point coordinates, closed state and role; visibility, names, measurements and draft paths do not invalidate the plan. Ring validation and existing polygon area/union checks reject invalid/outside holes or empty usable area. Overlapping holes are union-subtracted.

Upper lines run perpendicular to the deck direction; lower lines run parallel at a separate elevation. Clipping partitions only at outer/void boundary crossings. Cross-layer contacts never cut members. Lower lines and foot points require explicit intervals. Contacts, feet and splices are preliminary undesigned objects. All members remain productionReady=false and plans require technical approval. Stock overflow generates an undesigned splice requirement with at=null without cutting the continuous geometry. Kerf is stored without optimization.

Actual rows require all five board dimensions/gaps. Full-width rectangular row intervals are intersected over polygon vertex levels and their slabs, rather than clipping only row centrelines. Each resulting interval restarts its own piece sequence; edge gap is applied on both longitudinal interval ends. Crosswise rows use boardWidth and boardGap. Pieces advance by deckLength and explicit jointGap. No global seam coordinates are invented.

Endpoint support centres lie half a profile width inward from each deck end. Thus the physical outward face meets that end exactly. Paired seam support faces have the explicit deck joint gap between them. installationGap means the minimum clear gap between those faces: jointGap < installationGap warns and leaves every joint unverified. It does not invent cantilevers or move endpoints. doubleJointSupport=false omits seam-specific supports and warns. Short pieces that cannot accommodate two separate endpoint support widths warn. Support verification checks the entire row width, exact member face, profile footprint warning and overlap warnings. Joint.verified denotes only these geometric checks, never structural approval.

Refresh preserves all member endpoints and IDs, including deletions, and recalculates member lengths, elevations, stock flags/splices, contact IDs, warnings and joint verification. It does not restore removed members or feet, and does not move existing feet when a lower member moves. Missing/off-member feet and support spacing violations warn. Automatic feet are generated only during initial generation. Validation independently examines current member coordinates for spacing, physical footprint, contact, endpoint support, stock and source staleness.

Numerical limits: FRAMING epsilon 0.00001 mm; maximum 20,000 members, 5,000 rows and 50,000 deck pieces; automatic support grid bounded to 20,000 points. Drawing limits: 10,000 paths/points and coordinates ±100,000,000 mm. Excess candidate grids throw before their generation. Cross-layer candidate pairs and conservative upper-layer pair combinations are each capped at FRAMING.maxPieces (50,000), checked before contact/overlap work; connections are separately capped at 50,000. A 301×301 grid is rejected deterministically. Algorithms are synchronous and intended for ordinary deck plans; near-limit complex polygons and densely differing row seams can be expensive. Same-layer upper section overlaps are flagged rather than silently merged into physically impossible members. Geometry uses floating point arithmetic; comparison tests use epsilon where intersection arithmetic has machine roundoff.

Limitations: conservative row rectangles can leave unused wedges on sloping/concave boundaries; irregular/void footprints and any unused crosswise remainder produce DECK_COVERAGE_INCOMPLETE; physical profile width along irregular/void boundaries may be unproven and explicitly warns. Perimeter lines represent boundary centre geometry and can consequently warn about physical width extending outside the domain. Diagonal manual members receive generic upper/lower point-intersection contacts at matching elevations, but cannot obtain the axis-aligned row endpoint proof. They warn UPPER_ORIENTATION_UNPROVEN and UPPER_SPACING_UNPROVEN and are excluded from perpendicular spacing proof, preventing their start coordinate from concealing an unsupported slab gap. Editing a joint support into a diagonal invalidates affected endpoint/joint verification. Collinear overlapping members have no unique crossing and require separate connection design. No load/span, footing, weld, fastener, bearing capacity, engineering safety, cut schedule or optimization is certified. Explicit lower/support spacings are inputs, not safe recommendations.

Verification: tests were first run failing on absent engine exports, then implemented. 18 engine tests pass covering 6×4m, 10×10m, L/U footprints, multiple and overlapping holes, row-local split starts, 3000/4500/6000/7500 lengths, exact faces/joint clearance, direction rotation, deterministic geometry/codes, separate elevations, continuous crossings, exact lengths, stock flags, source signatures, manual deletion/refresh, invalid settings/outside holes and candidate limits. Latest strict project typecheck (`npx tsc --noEmit`) passed. Root integration owns the final full suite and native packaging.
